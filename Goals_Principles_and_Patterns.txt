2.1 Goals, Principles, and Patterns
In object-oriented programming, the primary components around which everything revolves are called objects, as the term suggests. 
These objects are specific, concrete instances created from classes, which act as blueprints or templates. A class defines the structure and behavior that its objects will have, but it also serves another critical purpose: it provides a clean and simplified interface to the outside world. 
Instead of exposing all the inner details of how an object works, a class carefully controls what is visible and accessible. This ensures that users of the object only see what they need to see — nothing more, nothing less.

Typically, a class includes definitions for data fields, also referred to as instance variables, which represent the state or properties of an object. 
Alongside these, it also defines methods, which are the actions or behaviors that an object can perform. This separation between the internal implementation and the external interface is a fundamental idea in object-oriented design. 
It allows for greater modularity, maintainability, and clarity in software development.

By following this model, object-oriented programming aims to achieve a number of key goals. These include making code easier to understand, reuse, and extend. 
Moreover, this paradigm is guided by a set of well-established design principles and patterns that help developers build systems that are both robust and adaptable. In this chapter, we will delve deeper into these goals, principles, and the commonly used design patterns that embody them.
